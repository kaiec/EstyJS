Atari ST

The Atari ST was a 16 bit home computer that was very popular in the late 80's and early 90's. It was the direct competitor of the Commodore Amiga and both machines were based upon the 68000 CPU. It was first released in 1985 and was very sucessful in the professional music industry due to having MIDI ports as standard.

EstyJS 2.0

EstyJS is an emulator for the Atari ST, written in 100% pure JavaScript, originally developed by Darren Coles. Since 2024 and the release of EstyJS 2.0, the project is maintained by Kai Eckert. The source code is available on GitHub. Please use GitHub issues for feedback, bugs and ideas.

EstyJS is not a full emulation and focuses on running games or old software for demonstration purposes. Notable limitations:

  • Copy protection that relies on disk rotation or timing is not emulated, so some original disks still refuse to run.
  • No writing to floppies. Disks are reported to TOS as write protected.
  • Joystick port 0 is not emulated, so two player games do not work. A connected gamepad takes over from the cursor keys.
  • Timer pulse width & high accuracy < 1 scanline is not supported.
  • No border effects (as used by some demos), only the official resolutions are supported.

Usage

  • Click a floppy drive to insert a disk image. See below for the formats EstyJS reads.
  • Click the ROM slot to use a different TOS image (.img) instead of the bundled EmuTOS.
  • Use the middle mouse button to realign the mouse pointer if necessary.
  • Joystick 1 is emulated using cursor keys and ctrl (or a real usb joypad). The Joystick button turns that off, so that the cursor keys and ctrl reach the ST as keys again.

Keyboard

Keys are taken by position, not by the character printed on them, so the keyboard layout of the host makes no difference: the key where a US keyboard has Y is the ST's Y key, whatever a German or French keyboard calls it. Everything sits where it looks, apart from the keys the ST has and a PC does not:

  • Undo is Page Up, Help is Page Down.
  • The ISO key (< > on a European ST) is the key beside the left shift key.
  • The keypad's ( and ) are Num Lock and Scroll Lock.
  • Cursor keys and ctrl are joystick 1 until the Joystick button is switched off.

Note that the ST's operating system here uses a US keyboard table, so the letter the ST receives is the one at that position on a US keyboard. That is what games expect, since they read the key position rather than the character.

Disk images

Atari ST disks have been imaged in a number of formats over the years, and they fall into two groups. Sector level formats store the data a normal disk holds. Track level formats store the magnetic layout of the disk itself, which is what it takes to preserve the copy protection of original game disks. EstyJS reads:

  • .st – a raw dump of every sector, with no header. The most common format, and the one to convert to if in doubt.
  • .msa – Magic Shadow Archiver: a header plus one run length encoded block per track. Single and double sided images both work.
  • .stx – Pasti, the format used to preserve original disks. The address field of every sector is read from the image and matched the way the disk controller matches it, so disks that number their sectors unusually, mark a sector as damaged, or leave bytes deliberately unstable behave as they did on the real machine. Whole track reads are answered from the image as well, which is what a number of protected originals check.
  • .zip – an archive containing one .st, .msa or .stx image.
  • .sts – not a disk image at all, but a Steem memory snapshot. It restores a whole machine state and is loaded through the same button.

What .stx support does not cover is time. The disk does not rotate: there is no index pulse, sectors are found immediately rather than when they come round, and the read time recorded for each sector is ignored. Protections that measure how long a read takes, or where on the track the head is, therefore still fail. Writing to a .stx image and formatting are not supported either.

Everything else is not read at all. .dim (FastCopy Pro) is sector level and could be added. .ipf and .ctr (Software Preservation Society, KryoFlux) need the closed source CAPS library; .stt and .stw (Steem), .scp (SuperCard Pro) and .hfe (HxC) are formats for other emulators and for floppy emulator hardware. Gzipped images (.st.gz, .msa.gz) are not unpacked, and there is no hard disk emulation of any kind, so ACSI and IDE images cannot be used either.
